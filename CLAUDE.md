## Project Overview

This is a **Battery Management System (BMS)** firmware for a 3S LiPo battery pack, running on a **STM32G491RETx** (ARM Cortex-M4F @ 170 MHz) on a NUCLEO-G491RE development board. It is bare-metal (no RTOS), written in C, built with GNU Make + ARM GCC.

## Build Commands

All build artifacts are in `Debug/`. The Makefile is generated by STM32CubeIDE.

```bash
# Build
cd Debug && make

# Clean build
cd Debug && make clean
```

**Toolchain required**: `arm-none-eabi-gcc` (GNU Tools for STM32). Output is `Debug/NUCLEO_G491RE_Test.elf`.

**Flashing**: Done via STM32CubeIDE or ST-LINK programmer — not via make.

## Architecture

### Hardware Peripherals

| Peripheral | Interface | Purpose |
|---|---|---|
| INA228 | I2C2 (addr 0x40) | Current/voltage sensing (20-bit ADC) |
| SSD1306 OLED | I2C3 (addr 0x78) | 128×64 display, 5 pages of data |
| NTC Thermistor | ADC1 CH1 | Temperature (Steinhart-Hart equation, β=3988K, 27kΩ/10kΩ divider) |
| MOSFET | GPIO PB5 | Load disconnect — HIGH = connected |
| User Button (B1) | GPIO | Page navigation, 50 ms debounce |

### Main Loop (`Core/Src/main.c`)

Superloop at ~10 ms tick with two independent timers:
- **200 ms**: Sample voltage, current, temperature → update SOC, fault detection, MOSFET control
- **250 ms**: Refresh OLED display

### SOC Tracking

1. **Initial SOC** estimated from OCV lookup table (11-point table for 3S LiPo, 9.0V–12.6V)
2. **Coulomb counting** accumulates `current × Δt` against a 2.2 Ah nominal capacity
3. **Light OCV correction** applied when current < 50 mA to reduce drift

### Fault Detection

| Fault | Condition | Action |
|---|---|---|
| `FAULT_WRONG_TEMP` | Temperature > 60°C | Display fault screen, halt loop |
| MOSFET cutoff | Temperature > 30°C or NaN | Open MOSFET (PB5 LOW) |
| Overcurrent | > 400 mA for 10 s | Fault state |
| Undercurrent | < 6 mA for 10 s | Fault state |

Fault state requires hardware reset to clear.

### Display Pages (cycled by B1 button)

`SOC` → `TEMP` → `VOLT` → `CURR` → `TIME` (time-to-empty, 10 s rolling average)

### Key Source Files

- `Core/Src/main.c` — all application logic: INA228 driver, NTC conversion, SOC algorithm, fault detection, display rendering, main loop
- `Core/Src/ssd1306.c` / `Core/Inc/ssd1306.h` — SSD1306 I2C driver, page-based framebuffer
- `Core/Inc/font5x7.h` / `Core/Src/font5x7.c` — 5×7 bitmap font
- `STM32G491RETX_FLASH.ld` — linker script for normal flash execution
- `NUCLEO_G491RE_Test.ioc` — STM32CubeMX pin/peripheral configuration (do not hand-edit)

### HAL-Generated Files

`Core/Src/stm32g4xx_it.c`, `stm32g4xx_hal_msp.c`, `system_stm32g4xx.c`, and all files under `Drivers/` are generated or provided by ST — avoid editing them directly. Re-run STM32CubeMX to regenerate if peripheral config changes.

## GitHub Sync Rules (MANDATORY)

**Remote**: `https://github.com/1zehaoyu1/individual-project` (branch: `main`)

### Session Start

At the beginning of every session, run:
```bash
git pull origin main
```
to sync the latest remote state before making any changes.

### After Every Significant Update

A "significant update" includes: any change to logic in `main.c`, new features, bug fixes, parameter tuning, or structural changes. After completing such work, commit and push using this format:

**Commit message format**:
```
[Update #N] <brief description>

Date: YYYY-MM-DD
Changes:
- <what was changed and why>
- <what was changed and why>
```

Determine N by checking existing tags: `git tag --sort=version:refname | tail -1`, then increment.

**Steps**:
```bash
# 1. Stage changed files (never use git add -A blindly)
git add <specific files>

# 2. Commit with the format above
git commit -m "[Update #N] ..."

# 3. Tag the update
git tag vN.0

# 4. Push commit and tag
git push origin main
git push origin vN.0
```

### Strict Rules

- **NEVER force-push** (`--force`, `-f`) to any branch.
- **NEVER delete files** from the repository. If a file is obsolete, leave it in place or add a comment — do not `git rm` it.
- **NEVER rewrite history** (`git reset --hard`, `git rebase` that removes commits, `git commit --amend` on pushed commits).
- Only push to `main`. Do not create or push to other branches without explicit user request.
- Build artifacts (`*.o`, `*.elf`, `*.d`) are excluded by `.gitignore` — do not force-add them.
